## 1. Git 한눈에

### 비유

| Git 말 | 비유 |
|---|---|
| 저장 (Ctrl+S) | 공책에 연필로 쓰기 — 기록이 안 남는다 |
| 커밋 (commit) | 그 순간을 **사진으로 찍어 앨범에 붙이기** — 언제든 돌아갈 수 있다 |
| 브랜치 (branch) | 앨범을 복사해 **따로 실험하는 갈래** — 망쳐도 원본(main)은 멀쩡하다 |
| 병합 (merge) | 실험이 성공하면 갈래를 원본 앨범에 합치기 |
| 원격 (GitHub) | 앨범을 인터넷 금고에 보관 — push 로 올리고 pull 로 받는다 |

### 파일이 지나가는 길

```
작업 폴더  ──git add──▶  스테이징(올릴 준비)  ──git commit──▶  내 저장소  ──git push──▶  GitHub
                                                                   ◀──git pull───
```

### 명령어 표

미션 필수 7종은 ★. 「사용 여부」는 미션 제출 전에 다 ✅ 가 돼야 한다.

| 명령 | 하는 일 | 예시 | 사용 여부 (2026-11-10) |
|---|---|---|---|
| ★ `git init` | 지금 폴더를 Git 저장소로 만든다 | `git init` | ❌ — 저장소를 GitHub 에서 만들어 clone 했기 때문. 13단계에서 따로 한 번 친다 |
| ★ `git clone` | GitHub 저장소를 통째로 내려받는다 | `git clone 주소` | ⚠️ Claude 가 대신 침 → 13단계에서 직접 |
| ★ `git add` | 커밋할 파일을 고른다 | `git add main.py` | ⚠️ Claude 가 대신 침 → 2단계에서 직접 |
| ★ `git commit` | 고른 파일을 사진 찍듯 기록한다 | `git commit -m "Feat: ..."` | ⚠️ Claude 가 대신 침 → 2단계에서 직접 |
| ★ `git push` | 내 기록을 GitHub 에 올린다 | `git push origin main` | ⚠️ Claude 가 대신 침 → 2단계에서 직접 |
| ★ `git pull` | GitHub 의 새 기록을 받아 온다 | `git pull` | ❌ → 3단계 · 13단계 |
| ★ `git checkout` | 브랜치를 옮기거나(`-b` 면 새로 만들며) 옮긴다 | `git checkout -b feature/quiz` | ✅ 직접 침 |
| `git merge` | 다른 브랜치를 지금 브랜치에 합친다 | `git merge --no-ff feature/quiz -m "..."` | ❌ → 2단계 |
| `git status` | 지금 브랜치 · 고친 파일 · 올릴 준비된 파일 | `git status` | 수시로 |
| `git branch` | 브랜치 목록 (`*` 가 지금 위치) | `git branch` | 수시로 |
| `git log` | 기록 보기 | `git log --oneline --graph --all` | 수시로 |
| `git diff` | 마지막 커밋 뒤로 무엇을 고쳤나 | `git diff` | 커밋 전 |

명령은 VSCode 터미널에 치거나, Claude 채팅창 맨 앞에 `!` 를 붙여 친다.

## 2. 매 단계 똑같이 도는 한 바퀴

모든 기능 단계는 이 순서다. 4단계부터는 이 블록의 `xxx` 만 바꿔 쓴다.

```
# ① 최신 main 에서 출발
git checkout main
git pull

# ② 새 갈래 만들기
git checkout -b feature/xxx

# ③ 코드 작성 → 실행해서 시험
python main.py

# ④ 무엇을 고쳤나 확인 → 고른 파일만 기록
git status
git diff
git add quiz_game.py        # git status 에 나온 고친 파일 이름을 적는다
git commit -m "Feat: xxx 구현"

# ⑤ main 에 합치고 GitHub 에 올리기
git checkout main
git merge --no-ff feature/xxx -m "Merge: xxx 기능 병합"
git push origin main
```

꼭 지킬 셋:

1. **`git add .` 대신 파일 이름을 적는다.** 엉뚱한 파일(개인 메모, `state.json`)이 공개 저장소에 올라가는 사고를 막는다.
2. **merge 에는 `--no-ff` 를 붙인다.** 안 붙이면 그래프가 일직선이 되어 제출 스크린샷에 "브랜치를 나눴다 합친 모양"이 안 보인다.
3. **merge 에는 `-m "메시지"` 를 붙인다.** 안 붙이면 vim 편집기가 열린다 (열렸으면 5장 참고).

### 커밋 메시지 모양

| 머리말 | 언제 | 예시 |
|---|---|---|
| `Feat:` | 기능을 새로 만들 때 | `Feat: 퀴즈 풀기 기능 구현` |
| `Fix:` | 잘못된 동작을 고칠 때 | `Fix: 빈 입력 시 프로그램 종료되는 문제 수정` |
| `Docs:` | 문서만 고칠 때 | `Docs: README 실행 방법 추가` |
| `Refactor:` | 동작은 그대로, 코드 정리만 | `Refactor: QuizGame 책임 분리` |
| `Merge:` | 브랜치를 합칠 때 | `Merge: 퀴즈 풀기 기능 병합` |

"수정", "update" 처럼 내용이 안 보이는 메시지는 미션이 「형식적인 커밋」으로 본다.

## 5. 막혔을 때

| 상황 | 해결 |
|---|---|
| 지금 어디인지 모르겠다 | `git status` → `git branch` → `git log --oneline --graph --all` 순서로 본다 |
| 브랜치를 안 따고 main 에서 코드를 고쳤다 | **커밋 전이면** `git checkout -b feature/xxx` — 고친 내용이 그대로 따라온다 |
| 엉뚱한 파일을 `add` 했다 | `git restore --staged 파일이름` — 올릴 준비만 취소, 파일 내용은 그대로 |
| 커밋 메시지에 오타 (push 전) | `git commit --amend -m "고친 메시지"` |
| 커밋 메시지에 오타 (push 후) | 그대로 둔다. 이미 올라간 기록을 고치려면 강제 푸시가 필요하다 — 하지 않는다 |
| 이상한 편집기(vim)가 열렸다 | `Esc` 누르고 `:wq` 입력 후 Enter (저장하고 나가기) |
| push 가 `rejected` 로 거절됐다 | GitHub 에 내가 없는 기록이 있다는 뜻. `git pull` 먼저 하고 다시 push. **`--force` 는 쓰지 않는다** |
| merge · pull 중 `CONFLICT` (충돌) | 파일을 열면 `<<<<<<<` · `=======` · `>>>>>>>` 표시가 있다. 남길 내용만 두고 표시 세 줄을 지운 뒤 `git add 파일` → `git commit -m "Fix: 병합 충돌 해결"`. 모르겠으면 Claude 에게 보여 준다 |
| `LF will be replaced by CRLF` 경고 | 무시해도 된다. 윈도우와 맥의 줄바꿈 표시 차이 |
| checkout 이 `would be overwritten` 으로 거절 | 커밋 안 한 수정이 있다는 뜻. 먼저 커밋하거나, Claude 에게 상황을 보여 준다 |
